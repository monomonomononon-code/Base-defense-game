# バランス設計・調整ガイド

調整元は `src/game/data.ts`。Lv1→55の実エンジン監査結果、購入除外比較、残した山場は [balance-audit.md](balance-audit.md)。全Lv数値は [levels.csv](levels.csv) を参照してください。

## レベルと敵

- 次のLvまでの経験値：`round(75 + (Lv−1) × 32 + (Lv−1)² × 10.5)`。Lv55は0。
- 基礎HP：`120 + (Lv−1) × 19`、基礎攻撃：`18 + (Lv−1) × 3.8`。
- 敵HP：`役割の基礎HP × 1.085^(Lv−1) × 1.7`。ボスはさらに2.1倍。
- 敵攻撃：`役割の基礎攻撃 × 1.097^(Lv−1)`。
- 敵経験値：`基礎経験値 × (1 + Lv × 0.21)`。敵コイン：`基礎コイン × (1 + Lv × 0.11)`。
- 自分より4Lv超低い敵は経験値を段階減衰、最低8%。護符と補給の経験値倍率も適用。
- 追跡者・高速型はLv10以降に移動速度が上昇。係数は `enemyStats()`。

経験値の余剰は次のレベルへ持ち越し、Lv55で上限処理。最初の防衛ボス撃破後は全地域へ入場可能。敵の指数成長により「入れるが危険」を表現します。

## 主人公・装備

- 攻撃：基礎攻撃 ×（1＋攻撃強化×0.12＋武器×0.16＋鍛冶屋×0.08）× 武器節目倍率 × 補給倍率。
- 武器+6/+12/+18の節目倍率は1.13/1.26/1.39。名前も変わります。
- HP：基礎HP ×（1＋HP強化×0.15＋防具×0.13）。防具+6/+12/+18で被ダメージを6/12/18%軽減。
- 射撃間隔：0.65秒 /（1＋速度強化×0.12）。射程：245＋強化×18。移動：172×（1＋強化×0.05）。
- 会心：6%＋護符×1.8%、会心ダメージ1.65倍。護符は1段階につき経験値+3.5%。
- 装備価格は1.30倍ずつ上昇。鍛冶屋は1段階につき3.5%、最大35%割引。
- 鍛造上限：初期+4、鉱山+12、山岳+14、廃都市+18。ドロップは鍛造制限とは独立。
- ドロップ基準は地域Lv/4、12%で+2上振れ。防衛の装備帯は実際の地域討伐に連動。

## 防衛と遠征をつなぐ補給

防衛成功で補給2個、最大12個。遠征出発で1個消費し、その遠征中に攻撃+25%以上・経験値+20%・被ダメージ12%軽減。補給なしでも出発できます。

攻撃補給倍率には現在拠点Lv×2.2%、恒久訓練×0.6%も加算。回復施設は回復薬のCTを1段階3%（最大30%）短縮し、回復量を最大HPの1.8%分ずつ加算。補給中の遠征では施設Lv×最大HPの0.1%/秒を回復します。

守備隊威力は（12＋主人公Lv×2.5）×（1＋訓練×0.25）。砲台は2.7倍の威力と半径80の爆風。エリート・ボス・主人公優先・拠点優先敵への守備隊威力は通常の42%。主人公の攻撃にはこの減衰はありません。

拠点HPは650＋拠点Lv×260＋壁×190。拠点Lvによる被ダメージ軽減もあります。留守番判定では施設数に加えて訓練・壁・回復施設を参照し、壁は自動撃退時の損害も軽減します。

襲撃間隔は基本300秒、前哨地制圧で25秒ずつ延長（最大200秒）。3回に1回は主人公の防衛が必要。ウェーブ番号に比例するコイン報酬の増分は20ウェーブで頭打ち。

## 資源と上位成長

取得量の素材別係数は木材1、鉄0.45、結晶0.18。採取・宝箱・イベント・敵ドロップ等へ適用します。倉庫はコインと敵ドロップ素材を1段階8%増加。

汚染地帯の発見後、Lv10以降の上位強化は結晶6個から段階的に消費します。序盤の木材、中盤の鉄、終盤の結晶の用途を分けています。

主人公強化・訓練・鍛冶屋は第一拠点に保持する恒久値。第二拠点でも共有。第二拠点の28%割引は現地施設・兵士のみへ適用し、恒久強化への二重割引を防ぎます。

## 進行と検証

序盤は雇用、森・廃村で弓塔と回復、鉱山で鍛冶屋と+6武器、荒野で第二拠点、山岳で砲台と+14鍛造、廃都市で+18、汚染地帯で上位結晶強化、という目標を設けています。順番は必須ではありません。

主要4型の疑似プレイヤーはLv55まで約42〜49分。初見の設計目安は60〜90分ですが、人間の実測ではありません。最終ボスはLv55以前にも撃破可能で、その後の育成は任意です。

```sh
npm test
npm run build
npm run balance
npm run simulate:all
npm run simulate:report
```

全条件のシミュレーションは109ケースあり、端末によって数分以上かかります。単独実行例は `npm run simulate -- sample balanced 17 casual`。ゲーム本体の戦闘・購入を使用し、ログのソースハッシュで数値の古さを検出します。現行コードを変えたら全条件を再実行してください。

`state.ts` は購入と恒久成長、`engine.ts` はAI・ダメージ・報酬・状態遷移を担当。効果を変えた場合はUI説明・テスト・本書も更新します。旧セーブのLvは維持し、新しい補給フィールドは0で補完します。
